1. Introduction

1.1 Purpose

This document defines the functional and non-functional requirements for the E-Book Library web application — a digital library platform where users can browse, read, bookmark, and interact with e-books; librarians can upload and manage content; and administrators oversee the system.

1.2 Scope

The system is a PHP 8+ web application with a MySQL/MariaDB backend, session-based authentication, RESTful JSON API, and a vanilla JavaScript frontend. Deployed on Apache (InfinityFree) with .htaccess routing or locally with PHP built-in server.

2. Functional Requirements

2.1 Authentication & Account Management

IDRequirementPriority
F-001The system shall allow users to register with name, email, and passwordHigh
F-002The system shall enforce a password policy: 8–72 characters, must include uppercase, lowercase, digit, and special characterHigh
F-003The system shall auto-login users immediately after successful registrationHigh
F-004The system shall allow users to log in with email and passwordHigh
F-005The system shall provide an optional "Remember Me" feature using token-based persistent sessions with 30-day expiryMedium
F-006The system shall regenerate session ID on loginHigh
F-007The system shall rate-limit login attempts to a maximum of 10 failed attempts per IP address per 60-second sliding windowHigh
F-008The system shall clear failed login attempt records upon successful loginMedium
F-009The system shall allow authenticated users to change their password by providing current and new passwordHigh
F-010The system shall allow authenticated users to permanently delete their own account, cascading to all associated dataHigh
F-011The system shall log out users by destroying the session, clearing cookies, and deleting all remember tokensHigh
F-012The system shall display a flash message "You have been signed out" upon logout redirectLow

2.2 User Roles & Permissions

IDRequirementPriority
F-013The system shall support three user roles: viewer, librarian, and adminHigh
F-014The system shall assign the viewer role by default to newly registered usersHigh
F-015Viewer users shall be able to browse the library, view book details, read books online, download books, bookmark books, log reading activity, set genre preferences, and manage their accountHigh
F-016Librarian users shall have all viewer privileges plus the ability to upload books (submitted as pending for admin approval)High
F-017Admin users shall have full system access including uploading books (auto-approved), approving/rejecting pending books, managing user roles, viewing audit logs, and deleting usersHigh
F-018Admin users shall not influence recommendation scores — their reading activity shall be silently discardedMedium
F-019Admin users shall have exclusive access to the admin dashboard; all other roles receive a 403 Forbidden responseHigh
F-020Unauthenticated users shall only be able to view book details and read/download approved books; all other features shall require authenticationHigh

2.3 Book Browsing & Search

IDRequirementPriority
F-021The system shall display a paginated grid of approved books (12 per page) sorted by most recentHigh
F-022The system shall allow users to filter books by genre via clickable genre tagsHigh
F-023The system shall allow users to search books by title or author using a text search field (LIKE match)High
F-024The system shall allow users to view only their bookmarked booksMedium
F-025The system shall display aggregate statistics: total books, total unique authors, total genres, and total activity eventsLow
F-026The system shall cache statistics for 5 minutes and genres for 1 hour via Cache-Control headersLow
F-027The system shall display personalized book recommendations (up to 6) for non-admin authenticated usersMedium
F-028The system shall persist filter state in URL query parameters for bookmarkable URLsMedium

2.4 Book Detail & Reading

IDRequirementPriority
F-029The system shall display a book detail page showing cover, title, author, genre, year, pages, descriptionHigh
F-030The system shall provide a PDF download link for approved booksHigh
F-031The system shall provide an inline PDF reader via an iframe embedded in the pageHigh
F-032The system shall serve inline PDFs with a 1-hour cache headerLow
F-033The system shall allow authenticated non-admin users to toggle bookmarks on/off for any approved bookMedium
F-034The system shall allow authenticated non-admin users to mark books as completedMedium
F-035The system shall log book_opened and book_completed activity events for non-admin usersMedium
F-036The system shall assign weight=2 for completed events and weight=1 for opened events for recommendation scoringMedium

2.5 Activity Tracking

IDRequirementPriority
F-037The system shall display a paginated history of the user's reading activity (30 items per page)Medium
F-038The system shall allow filtering activity history by event type: "Opened" or "Completed"Medium
F-039The system shall deduplicate activity entries when filtering by type, showing only the latest event per book per typeLow
F-040The system shall allow users to soft-delete individual activity log entriesMedium

2.6 Genre Preferences

IDRequirementPriority
F-041The system shall allow users to select their preferred genres from the available listHigh
F-042The system shall require a minimum of 3 genre selections before savingHigh
F-043The system shall automatically redirect newly registered users to the preferences page after registrationMedium

2.7 Book Upload

IDRequirementPriority
F-044The system shall allow librarians and admins to upload books via a form with title, author, description, genre, year, pages, cover image, and PDF fileHigh
F-045The system shall validate uploaded PDFs by file extension (.pdf) and magic bytes (%PDF)High
F-046The system shall enforce a maximum PDF upload size of 50 MBHigh
F-047The system shall optionally accept cover images (JPEG, PNG, GIF, WebP) and resize them to max 600px wide via GD library, converting to JPEG quality 85Medium
F-048The system shall auto-approve books uploaded by admins and set librarian uploads to pending statusHigh
F-049The system shall sanitize filenames by removing non-alphanumeric characters before savingMedium

2.8 Admin Dashboard

IDRequirementPriority
F-050The system shall display admin dashboard with aggregate statistics (total books, pending count, total users, activity events)High
F-051The system shall display a pending books table with approve/reject actionsHigh
F-052The system shall display an all-users table allowing admins to promote/demote users and delete accountsHigh
F-053The system shall record an audit trail for all admin actions: book approve/reject/edit, user role change, and user deletionHigh

2.9 Recommendation Engine

IDRequirementPriority
F-054The system shall calculate personalized book recommendations based on the user's genre preferences and completed-genre historyHigh
F-055The system shall score recommended books using weighted activity from the last 180 daysMedium
F-056The system shall exclude books the user has already interacted with from recommendationsHigh
F-057The system shall fill remaining recommendation slots with the most recently added books if fewer than requested limit are foundMedium

2.10 Maintenance

IDRequirementPriority
F-058The system shall provide a CLI maintenance script to archive activity logs older than 180 days (soft-delete)Low
F-059The system shall provide a CLI maintenance script to permanently purge soft-deleted logs that are older than 30 daysLow
F-060The system shall provide a 30-day grace period between soft-delete and hard-delete for audit purposesLow

4. Security Requirements

IDRequirementPriority
SE-001The system shall protect all non-GET API endpoints with CSRF tokens validated server-sideHigh
SE-002The system shall automatically attach CSRF tokens to all non-GET fetch requests via a global fetch overrideHigh
SE-003The system shall hash all passwords using PASSWORD_BCRYPTHigh
SE-004The system shall use HTTPS for all communications in productionHigh
SE-005The system shall use HTTP-only, SameSite=Lax session cookiesHigh
SE-006The system shall regenerate session IDs upon successful login to prevent session fixationHigh
SE-007The system shall use SHA-256 hashed remember-me tokens stored in the database (never store raw tokens)High
SE-008The system shall rotate remember-me tokens on each use (one-time use)Medium
SE-009The system shall restrict redirect URLs after login to a whitelist of allowed pathsMedium
SE-010The system shall block direct HTTP access to partials/, config/, database/, and vendor/ directoriesHigh
SE-011The system shall validate uploaded PDF files by both extension and magic byte content inspectionHigh
SE-012The system shall resize and re-encode uploaded cover images to mitigate image-based attacksMedium
SE-013The system shall sanitize uploaded filenames to prevent path traversalMedium
SE-014The system shall use prepared statements (via PDO) for all database queries to prevent SQL injectionHigh
SE-015The system shall escape user-generated content using htmlspecialchars() or DOM-based textContent for XSS preventionHigh
SE-016The system shall enforce role-based access control on both page-level and API-level with server-side verificationHigh
SE-017The system shall perform account deletion in a database transaction with rollback on failureMedium
SE-018The system shall log all admin actions in an immutable audit trail with timestamp, action type, target, and detailsHigh
SE-019The system shall enforce password complexity requirements on both client and server sideHigh
SE-020The system shall rate-limit login attempts to max 10 per IP per 60-second sliding windowHigh

IDRequirementPriority

D-002The system shall enforce unique email addresses per userHigh
D-003The system shall store user role as a string (viewer, librarian, admin)High
D-004The system shall store book metadata including title, author, description, cover URL, genre, ISBN, year, pages, file path, file size, uploader, status, and creation timestampHigh
D-005The system shall support book statuses: pending, approved, and rejectedHigh
D-006The system shall store activity logs with event type, weight, and soft-delete flagHigh
D-007The system shall maintain a many-to-many relationship between users and genres for preferencesHigh
D-008The system shall maintain a many-to-many relationship between users and books for bookmarksHigh
D-009The system shall enforce one review per user per book via a unique constraintMedium
D-010The system shall store audit trail details as JSON for flexible structured loggingHigh
D-011The system shall cascade delete user data across all related tables when a user is deletedHigh
D-012The system shall set genre_id to NULL on books when a referenced genre is deletedMedium
D-013The system shall seed the database with 5 initial genres: Sci-Fi, Fantasy, Romance, Non-Fiction, ThrillerHigh
D-014The system shall provide 3 demo user accounts (admin, librarian, viewer) for development and testingLow

9. Database Entity Summary

EntityTypeDescription
genresTableBook genre taxonomy (5 pre-seeded: Sci-Fi, Fantasy, Romance, Non-Fiction, Thriller)
usersTableUser accounts with bcrypt passwords; roles: viewer, librarian, admin
user_preferencesTableM:M user-to-genre preferences; composite PK; CASCADE on both FKs
booksTableBook catalog with metadata, file path, approval status; FK to genres (SET NULL) and users (CASCADE)
activity_logsTableUser reading events with weighted scoring and soft-delete flag; 3 composite indexes
reviewsTableUser ratings (1-5) and comments; UNIQUE(user_id, book_id)
remember_tokensTablePersistent login tokens (SHA-256 hashed); 30-day expiry; rotated on use
bookmarksTableM:M user-to-book bookmarks; composite PK
login_attemptsTableIP-based rate limiting records; standalone table with composite index on (ip, attempt_time)
audit_logsTableAdmin action audit trail with JSON details column
